📄️ Case Studies

30 real HackerOne cases, each written as a discovery-first reasoning challenge: hit the reasoning wall by hand, then see how a reasoning engine closes it.

📄️ Uber #361438

A bucket tagged confidential carries a policy that grants the whole internet read access — can you prove the contradiction from the static config alone?

📄️ Slack #404822

A public bucket policy paired with a Public Access Block that blocks nothing — can you tell from the config whether the toggle protects anything?

📄️ Shopify #1021906

A production API bucket tagged internal grants the public both read and list — can you tell from the config what an attacker can enumerate?

📄️ Omise #1474017

A CDN origin bucket is opened by both an ACL and a policy — can you tell from the config that fixing one path leaves the other wide open?

📄️ Zomato #507097

A bucket of user chat images is open by both ACL and policy, with listing on — can you tell from the config that the privacy harm comes from enumeration, not just read?

📄️ Shopify #57505

A bucket meant to serve images publicly also grants public listing — telling whether the extra permission is intentional or a leak.

📄️ Greenhouse #819278

Marketing assets are public by design, but the same grant also exposes the full inventory — separating intended exposure from disclosure.

📄️ Shopify #94502

A partial fix removed public listing but left public read and public write via ACL — judging whether remediation is actually complete.

📄️ Mapbox #202725

Bucket-level config looks locked down, but per-object ACLs make individual objects public — catching exposure the bucket settings hide.

📄️ Mozilla #2383486

A public bucket serves static content but also exposes a synced .git directory — distinguishing harmless public files from a source-code leak.

📄️ DoD #2083771

Reasoning that an exposed Jenkins console plus IMDSv1 forms a single credential-theft path, not two independent low findings.

📄️ Bime #121461

Reasoning that a live DNS record plus a claimable bucket name is a takeover primitive, even while the page returns a harmless 404.

📄️ DoD #918946

Reasoning that a dangling .gov CNAME is a high-trust takeover primitive while it still serves a harmless 404.

📄️ Khan Academy #1777077

Reasoning that a dangling website-hosting CNAME is a seamless takeover-and-session-theft primitive while it still returns a 404.

📄️ Tendermint #1397826

Reasoning that a dangling release-bucket CNAME referenced by install docs is a supply-chain takeover primitive while it still returns a 404.

📄️ Brave #1791558

An APT repository bucket was deleted but the DNS name and the community install guide still point at it — can you prove the reference is claimable from the static evidence alone?

📄️ Shopify #1295497

An EC2 instance was terminated and its Elastic IP released, but the DNS A record still points at the old address — can you prove the record is dangling from the static evidence alone?

📄️ Unikrn #254200

A presigned upload policy restricts keys to a prefix shared by every tenant — can you prove the prefix breaks tenant isolation from the policy alone?

📄️ Shopify #93691

A presigned POST policy scopes uploads to a prefix shared by all merchants — can you prove one merchant can overwrite another's files from the policy alone?

📄️ BCM #764243

A presigned POST policy uses an empty starts-with prefix, so any key in the bucket is a legal upload target — can you prove the write scope is unrestricted from the policy alone?

📄️ Shopify #98819

Anonymous write via ACL plus cross-account read via policy form a data-injection pipeline that neither setting reveals on its own.

📄️ Shopify #94087

A presigned URL scoped one prefix too wide lets one tenant write into another tenant's space — isolation that lives in a single Resource string.

📄️ Kubernetes #1580493

An EKS aws-auth mapping uses the AccessKeyID as the identity and hands it system:masters — turning a public string into full cluster admin.

📄️ AWS #3021451

A CloudTrail reads as fully configured, yet ElastiCache calls through a non-production endpoint generate no log entries at all.

📄️ AWS #3022516

A correctly configured trail still misses Amazon Forecast calls made through two non-production endpoints the service never delivers to CloudTrail.

📄️ HackerOne #43280

Both HTTP and HTTPS serve the same objects — can you prove, from the policy alone, that nothing is leaking on the wire?

📄️ Kubernetes #1238482

A controller reconciles security groups from annotations it never checks for ownership — can you spot the cross-tenant write before it happens?

📄️ Brave #1835133

A 404 today, a trojaned RPM repository tomorrow — can you tell that a harmless dangling reference is one registration away from supply-chain compromise?

📄️ HackerOne #1598347

A deleted widget bucket plus a live <script> tag — can you see that claiming the name turns a dead reference into attacker JavaScript on the parent domain?

📄️ IBM #2498255

A subsidiary's DNS outlived its bucket after a merger — can you tell that an inherited 404 is a branded takeover waiting for someone to claim the name?
